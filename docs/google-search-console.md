# Google Search Console SEO Guide

How to connect this site to Google Search Console, submit the sitemap,
and keep SEO healthy over time. The site is a Hugo build deployed to
GitHub Pages at `https://tacherasasi.github.io/`.

## 1. Deploy first

Search Console verifies and indexes the **live** site, so push first:

```bash
make build   # local check, must pass with no errors
git push     # .github/workflows/hugo.yaml deploys to Pages
```

Wait until the `Deploy Hugo site to Pages` workflow is green, then open
`https://tacherasasi.github.io/` and confirm it loads.

## 2. Verify site ownership

1. Go to [Google Search Console](https://search.google.com/search-console/)
   and click **Add property** → **URL prefix** →
   `https://tacherasasi.github.io/`.
2. Choose the **HTML tag** method. Google gives you a token like
   `dBw...X4`.
3. Put the token in `hugo.toml`, no `<meta>` editing needed:

   ```toml
   [params.seo]
   googleSiteVerification = 'PASTE_TOKEN_HERE'
   ```

   (There is also `bingSiteVerification` for Bing Webmaster Tools;
   same workflow at `https://www.bing.com/webmasters`.)
4. Rebuild, commit and push, then click **Verify** in Search Console.
   The token renders as `<meta name="google-site-verification">` in
   every page's `<head>` via `layouts/partials/seo-head.html`.

## 3. Submit the sitemap

1. In Search Console → **Sitemaps** → add `sitemap.xml`.
   The sitemap is auto-generated by Hugo (`[sitemap]` in `hugo.toml`)
   and lives at `https://tacherasasi.github.io/sitemap.xml`.
2. Expect ~90 URLs: home, about, writing, 13 posts, 10 project
   case studies, tag/category archives.
3. `robots.txt` (`https://tacherasasi.github.io/robots.txt`) already
   points crawlers at the sitemap. No action needed.

## 4. Request indexing for key pages

New/changed pages can take days to be discovered. Speed it up:

1. Search Console → **URL Inspection** → paste a URL →
   **Request indexing**.
2. Priority order:
   - `https://tacherasasi.github.io/`
   - `https://tacherasasi.github.io/posts/`
   - `https://tacherasasi.github.io/projects/`
   - `https://tacherasasi.github.io/projects/beamdrop/`
   - `https://tacherasasi.github.io/projects/ekilie-cloud/`
   - `https://tacherasasi.github.io/projects/vintlang/`
   - your 2-3 strongest posts.
3. Internal links do the rest: every post links to siblings
   ("Keep reading"), the home page links to featured projects,
   and section pages cross-link each other.

## 5. Keep new posts SEO-clean

`hugo new posts/my-post.md` scaffolds all required fields from
`archetypes/default.md`. Before publishing, fill in:

| Field         | Rule of thumb                                              |
|---------------|------------------------------------------------------------|
| `title`       | One H1 per page, under ~60 chars, keyword near the front   |
| `description` | ~150 chars, plain sentence, no quotes/HTML                 |
| `tags`        | 4-7 lowercase tags, reuse existing ones (`/tags/`)         |
| `categories`  | 1 value from: Backend, Systems Programming, Distributed Systems, DevOps, Web Development, Career |
| `keywords`    | 3-6 search phrases                                         |
| `images`      | OG image path, must exist in `static/images/`              |
| `lastmod`     | bump whenever you edit the body                            |

Medium imports (`python3 tools/medium_import.py <url>`) already emit
this frontmatter, with `medium:` kept as attribution. Keep the
canonical URL on this site so ranking accrues here, not Medium.

## 6. Monthly health check (15 minutes)

1. **Coverage** (Search Console → Pages): 0 errors. Redirects should
   only be intentional.
2. **Performance**: watch clicks/impressions for `beamdrop`,
   `vintlang`, `ekilie cloud`, `go escape analysis`. If impressions
   grow but CTR is low, rewrite that page's `description`.
3. **Enhancements**: structured data (`BlogPosting`, `BreadcrumbList`,
   `ItemList`) should show 0 errors.
4. **Core Web Vitals**: Hugo output is static and light; regressions
   usually come from new images. Keep images compressed, always set
   `width`/`height` or CSS size, keep `loading="lazy"` below the fold.
5. **Freshness**: update one old post per month (fix, extend, bump
   `lastmod`) and publish case studies for new projects under
   `content/projects/<slug>.md` with `slug:` set so the URL stays
   short (`/projects/<slug>/`).

## 7. What is already handled by the templates

- Title, meta description, canonical, Open Graph, Twitter cards
  (`layouts/partials/seo-head.html`).
- JSON-LD: WebSite, Person, BlogPosting, BreadcrumbList, project
  ItemList (`layouts/partials/seo-jsonld.html`).
- One H1 per page, breadcrumbs, author box, related posts, tag/category
  archives, RSS, custom 404, favicon + web manifest.
- Pagination safety: page 2+ of paginated lists emits
  `noindex, follow`.

Do not hand-edit generated tags into templates; fix data at the
source (frontmatter, `data/projects.yaml`, `hugo.toml`).
